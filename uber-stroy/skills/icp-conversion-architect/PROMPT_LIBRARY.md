# Prompt Library — ICP & Conversion Architect

Use these prompts after reading `SKILL.md`. Replace bracketed inputs with verified project context. Do not invent missing evidence.

## 1. ICP Discovery

> Выполни ICP Discovery для [продукт/рынок]. Изучи предоставленные материалы и реальные данные. Сегментируй аудиторию по задаче, триггеру покупки, последствиям нерешённой проблемы, бюджету, buying process, доступности и fit с исполнением. Составь ICP scorecard 1–5 с evidence/confidence. Выбери один beachhead ICP и объясни, кого пока не брать. Раздели Observed, Inferred, Hypothesis и Unknown. Не начинай с рекламных текстов.

## 2. Persona / Buying Committee

> Построй рабочие профили для [роли]. Для каждой роли определи ответственность, KPI, контекст дня, триггеры, functional/emotional/social jobs, pains, desired outcomes, current workaround, критерии выбора, возражения, proof required, customer vocabulary и полномочия в сделке. Отдели economic buyer, champion, user, evaluator, procurement/legal/finance и blockers. Не выдумывай цитаты. Заверши тем, что это значит для оффера и сообщения.

## 3. JTBD and Trigger Research

> Разбери последний реальный эпизод покупки/поиска решения в материалах [источники]. Выдели situation, trigger, desired progress, functional/emotional/social dimensions, current solution, push/pull/anxiety/habit forces. Сформулируй job statement формата «Когда…, я хочу…, чтобы…». Отдельно укажи подтверждённое и требующее интервью. Предложи 8–12 не наводящих вопросов для следующего разговора.

## 4. Voice of Customer Mining

> Проанализируй [звонки/интервью/CRM/переписки] и извлеки точные формулировки клиентов. Построй VoC таблицу: цитата, источник и дата, контекст, job, pain/outcome, частота, confidence, возможное применение. Сгруппируй повторяющиеся фразы, триггеры, возражения и слова клиента. Не переписывай цитаты как будто они дословные; отмечай пересказ отдельно.

## 5. Pain-to-Value Map

> Для ICP [роль] построй Pain-to-Value Matrix. Для каждой боли укажи trigger, frequency, impact, cost of inaction (только если подтверждаем), workaround, desired outcome, proof needed и product mechanism. Сопоставь с конкретными возможностями продукта. Пометь несоответствия, где продукт пока не способен закрыть боль. Выбери три наиболее сильные связки pain → mechanism → outcome.

## 6. Offer Architecture

> Создай архитектуру оффера для [ICP и ситуация]. Сначала сформулируй одну core value proposition, затем три альтернативных угла. Для каждого: audience, situation, problem, promised outcome, mechanism, differentiation, proof, limits, CTA, risk of overclaim. Отдели факты от предположений. Не обещай гарантий, сроков, ресурсов или финансового результата без доказательств и подтверждённой возможности исполнения.

## 7. Message House / Conversion Copy

> Построй Message House для [ICP]. Нужны core promise, три supporting pillars, подтверждения под каждым, objection responses, customer language, prohibited claims and primary CTA. Затем напиши hero, problem section, solution mechanism, proof, process, FAQ и CTA. Проверь message match и что текст звучит как речь клиента, а не корпоративная самопрезентация.

## 8. Creative Pack

> Создай 5 различающихся рекламных концепций для [ICP]. Для каждой укажи pain/trigger, insight, hook, headline, copy, visual story, composition, proof, CTA, channel/format, what-not-to-invent и hypothesis. Не делай пять вариаций одной фразы. Визуал должен показывать конкретную клиентскую ситуацию и механизм решения. Не генерируй fake client proof или читаемые надписи внутри картинки.

## 9. Landing Page Architecture

> Спроектируй mobile-first landing для [ICP, traffic source, conversion goal]. Сначала зафиксируй awareness level, offer, proof, objections and constraints. Затем выдай структуру блоков: цель, вопрос клиента, headline, copy, visual, proof, CTA, mobile adaptation and analytics event. Сформулируй поля формы и обоснуй каждое. Не вставляй весь плакат одним изображением: раскрой его идею отдельными нативными блоками. Не выдавай демо-форму за реально работающую отправку.

## 10. CRO Audit

> Проведи CRO аудит [URL/скриншоты/HTML]. Оцени ICP clarity, message match, offer, problem relevance, mechanism, proof, objections, CTA, friction, mobile UX, technical integrity, trust/compliance по 0–5. Для каждого дефекта приложи evidence, severity, hypothesis, fix, metric, guardrail и effort. Сначала перечисли release blockers. Не заявляй, что тестировал live page, если у тебя были только скриншоты или исходник.

## 11. Experiment Design

> На основе baseline [данные] предложи не более трёх CRO экспериментов. Каждый должен менять одну существенную переменную и включать hypothesis, control, variant, primary metric, guardrails, segment, sample/duration assumptions, success/fail/inconclusive criteria. Учитывай качество и коммерческую ценность лида, а не только сырую конверсию. Если выборки мало — предложи usability testing / interviews, а не ложный статистический вывод.

## 12. Sales Insight Loop

> Сопоставь результаты звонков и причины потерь [период] с действующим ICP и оффером. Найди, какие проблемы повторяются, какие ожидания не совпадают с продуктом, какие возражения не закрыты. Предложи точечные изменения в лендинге/креативе и вопросы discovery. Передай Growth Agent обновлённый ICP, customer phrases, offer, disqualification criteria и следующий эксперимент.

## 13. UBER STROY Owner Page

> Используй UBER STROY reference module. ЦА — собственник строительной компании/генподрядчик. Основная идея: «UBER STROY — нужные люди на ваши объекты». Раскрой экономический и управленческий контекст: сроки, стоимость, обязательства, контроль, рассеянные контакты и ручной поиск. Отдели подтверждённую услугу от неподтверждённых гарантий. Строй оранжево-чёрную промышленную визуальную историю: руководитель/объект → проблема недокомплекта → организованная команда → управляемый процесс → обсуждение задачи.

## 14. UBER STROY role variants

> Сделай отдельные message maps для: (1) собственника, (2) прораба, (3) мастера участка, (4) HR. Для каждого выбери одну ключевую ситуацию, language, objections, proof, offer and CTA. Не меняй только заголовок — меняй аргументацию и квалификацию. Бригадира/поставщика рабочей команды анализируй отдельной supply-side воронкой.

## 15. Production Release Review

> Проведи production release review лендинга. Проверь обещания, evidence, фото/права, мобильную адаптацию, доступность, ссылки, формы, success/error, webhook/CRM, UTM/analytics, privacy/consent, HTTP response, image dimensions/content-type, JS and live rendering. Выдай PASS / HOLD по каждому gate. Не присваивай PASS непроверенному компоненту.
